# Viewer Function Reference

This file documents the main exported viewer functions and helpers used by the viewer runtime.
It is intended as a quick reference for the current `viewer/` module exports and their roles.

## `viewer/main.js`

`viewer/main.js` exposes the exported `Viewer` object and core runtime entry points.

- `Viewer.MainInit()`
  - Initialize the viewer runtime.
  - Loads `viewer-settings.json`, configures the DOM container, sets up core state, starts the animation loop, and prepares the viewer for model loading.

- `Viewer.mainLoadModel()`
  - Load the current model from `core.fileObject`.
  - Handles all supported file formats, archive transformations, GLTF/GLB loading, and post-load scene preparation.

- `Viewer.mainLoadModelWrapper()`
  - Wrapper for `mainLoadModel()`.
  - Normalizes auto-paths and archive paths before delegating to the loader.

- `Viewer.prepareSandboxScene()`
  - Reset the viewer for sandbox mode.
  - Clears loaded objects, resets camera and controls, and shows sandbox UI hints.

- `Viewer.setModelPaths()`
  - Parse and populate `core.fileObject` from `core.fileObject.originalPath`.
  - Sets `filename`, `basename`, `extension`, `path`, `uri`, and `relativePath`.

- `Viewer.normalizeFileUrl(rawUrl)`
  - Normalize source URLs and Drupal `public://` paths.
  - Converts relative model attributes into canonical browser URLs.

- `Viewer.normalizeDrupalFilesPath(path)`
  - Normalize Drupal file paths by stripping `sites/default/files` prefixes and trimming slashes.

- `Viewer.normalizeArchiveModelPath(path)`
  - Fix archive-derived model paths by injecting a `/gltf/` segment when needed.

- `Viewer.applyCameraOverridesFromUrl()`
  - Apply camera position, camera target, and FOV overrides from URL query parameters.

- `Viewer.toggleFullscreen()`
  - Enter or exit fullscreen mode for the viewer container.

- `Viewer.updateSize()`
  - Resize the renderer, camera, GUI, metadata, and action menu when the viewport changes.

- `Viewer.setCameraProjection(projection)`
  - Switch the viewer camera between perspective and orthographic projection.

- `Viewer.toHexColor(input)` / `Viewer.toThreeColor(input)`
  - Normalize different color input formats into numeric or `THREE.Color` values.

- `Viewer.disposeObjectResources(object)`
  - Dispose of mesh geometry and material resources for an object tree.

- `Viewer.removeAndDisposeFromScene(object)`
  - Remove an object or object array from the scene and dispose its resources.

- `Viewer.resetLoadedModelState()`
  - Clear viewer state related to loaded models, annotations, selection, and helper objects.

- `Viewer.reportError(error, options)`
  - Report viewer errors consistently to console, toast notifications, and E2E state.

- URL and parameter parsing utilities:
  - `Viewer.parseBooleanParam(value)`
  - `Viewer.parseFloatParam(value)`
  - `Viewer.parseVector2Param(value)`
  - `Viewer.parseVector3Param(value)`
  - `Viewer.formatVector3Param(vector)`

- Viewer support utilities:
  - `Viewer.getSupportedFormatsText()`
  - `Viewer.getSupportedArchiveFormatsText()`
  - `Viewer.getDistanceMeasurementScaleMeters()`
  - `Viewer.formatMeasuredDistance(rawDistanceInModelUnits)`
  - `Viewer.toggleAutoRotateByKeyboard()`
  - `Viewer.onViewerKeyDown(event)`


## `viewer/animations.js`

Playback of animation clips shipped with the model (glTF/GLB, FBX, DAE, KMZ, three.js JSON). Test model: `viewer/examples/animated.glb`, generated by `scripts/generate-animated-sample.py`.

- `Viewer.setupModelAnimations(object)`
  - Build an `AnimationMixer` for the clips on `object.animations`, show the player bar and apply `viewer.animation` settings. Called by `loadModel()` after the model is added to the scene.

- `Viewer.selectAnimation(selection, { play })`
  - Switch to a clip by index, or `"all"` to play every clip together.

- `Viewer.playAnimation()` / `Viewer.pauseAnimation()` / `Viewer.toggleAnimationPlayback()`
  - Control playback. The `K` key toggles playback when the canvas has focus.

- `Viewer.setAnimationTime(seconds)` / `Viewer.setAnimationSpeed(speed)` / `Viewer.setAnimationLoop(loop)`
  - Scrub, change speed and switch between looping and playing once.

- `Viewer.disposeAnimations()`
  - Stop playback and remove the player. Called when a model is unloaded.


## `viewer/timeline.js`

4D timeline: the model's stages on a year axis, faded into each other for any year chosen. Stages come from the model (glTF scene extras `timeline`, or node extras `year`) and/or the manifest (`AIM3DViewer.timeline`, see `manifesto/AIM3DViewer-schema.md`). Test model: `viewer/examples/4D/WolpaSynagogue_4D.glb`, manifest `wolpa-synagogue-aim3d-local-4d.json`.

- `Viewer.setupTimeline(object)`
  - Read the stages of `object`, show them at the start year and build the panel. Called by `setupModelAnimations()`, which then leaves out the clip that only switches the stages (`Viewer.isTimelineClip(clip)`).

- `Viewer.setTimelineYear(year, { immediate })` / `Viewer.stepTimeline(direction)`
  - Go to a year (eased, as a short time-lapse, unless `immediate`) or to the previous / next point.

- `Viewer.playTimeline()` / `Viewer.pauseTimeline()` / `Viewer.toggleTimelinePlayback()`
  - Playback, held on `documented` stages. The `K` key toggles it when the model has no animation clips.

- `Viewer.showTimelineStagesAt(year)`
  - Show the stage of `year` without fading and without changing the year shown (one side of the comparison view); `renderTimelineStages(0, { force: true })` puts the shown year back.

- `Viewer.apply3IFManifestTimeline(config)` / `Viewer.getTimelineForExport()`
  - Manifest import and export of `AIM3DViewer.timeline`.

- `Viewer.disposeTimeline()`
  - Restore the stage nodes and materials and remove the panel. Called when a model is unloaded.


## `viewer/editor/compare.js`

Reconstruction variants and the comparison view. Variants are alternative hypotheses of the same object, each a set of model nodes; one is shown at a time. The comparison view draws the scene twice per frame, each side showing a variant or a year of the 4D timeline, split by a divider (`swipe`) or side by side (`split`). Variants come from the model (glTF scene extras `variants`, or node extras `variant`) and/or the manifest (`AIM3DViewer.variants`, `AIM3DViewer.compare`, see `manifesto/AIM3DViewer-schema.md`). Example manifest: `manifesto/examples/tempietto-aim3d-variants.json`.

- `Viewer.setupVariants(object)`
  - Read the variants of `object`, show the active one and build the panel; open the comparison the manifest or URL asks for. Called by `setupModelAnimations()` after `setupTimeline()`.

- `Viewer.setActiveVariant(id)` / `Viewer.getActiveVariant()`
  - Show another variant / the variant shown.

- `Viewer.openCompare({ mode, left, right, position })` / `Viewer.closeCompare()` / `Viewer.toggleCompare()`
  - Open or close the comparison; a side is `{ variant }`, `{ year }`, or a bare id or year. The timeline panel's compare button opens its first and last stage.

- `Viewer.setCompareMode(mode)` / `Viewer.setCompareSide("left" | "right", side)` / `Viewer.setComparePosition(share)`
  - Change the comparison while it is open.

- `Viewer.renderCompareFrame(renderFrame)`
  - Draw both sides (scissor or half viewports); called by `animate()` instead of `renderFrame()`, returns `false` when nothing is compared.

- `Viewer.apply3IFManifestVariants(variants, compare)` / `Viewer.getVariantsForExport()` / `Viewer.getCompareForExport()`
  - Manifest import and export.

- `Viewer.disposeVariants()`
  - Show all variant nodes again and remove the panel and the comparison. Called when a model is unloaded.


## `viewer/editor/photo-overlay.js`

Historical photos over the model, each with the camera it was taken from (`AIM3DViewer.photos`, see `manifesto/AIM3DViewer-schema.md`). The panel opens from *Annotations > Historical photos*. Example manifest: `manifesto/examples/tempietto-aim3d-photos.json`.

- `Viewer.openPhoto(id, { fly })` / `Viewer.closePhoto()`
  - Fly to the photo's view, set the timeline to its `year` and lay the photo over the canvas (fitted to the canvas height, which the vertical field of view spans). Moving the camera hides it until `Viewer.flyToPhotoView()`.

- `Viewer.setPhotoOpacity(value)` / `Viewer.setPhotoSwipe(enabled, position)`
  - Fade the photo in, or cut it by a divider instead.

- `Viewer.setPhotoAligning(enabled)` / `Viewer.setPhotoFov(fov)` / `Viewer.setPhotoRoll(degrees)` / `Viewer.savePhotoView()`
  - Line a photo up by hand: the photo stays while the camera moves; the lens and the tilt are matched, then the pose is saved as its view.

- `Viewer.addPhoto({ src | service | file, label, year })` / `Viewer.removePhoto(id)`
  - Add a photo taken from the current view (a IIIF Image API `info.json` or `service` is asked for the image at up to 2000 px), then align it. Photos from a file are not exported.

- `Viewer.togglePhotosPanel(open)` / `Viewer.apply3IFManifestPhotos(list)` / `Viewer.getPhotosForExport()` / `Viewer.disposePhotos()`
  - Panel, manifest import and export, clean-up when a model is unloaded.


## `viewer/editor/sun-study.js`

Sun and shadows (*Lights > Sun and shadows*): the sun at the model's place (`AIM3DViewer.location`) on a day and hour (`AIM3DViewer.sun`), casting shadows; the year is the 4D timeline's. Example manifest: `manifesto/examples/tempietto-aim3d-sun.json`.

- `Viewer.setSunStudy(enabled)`
  - Switch the sun on (at the day and hour it is now at the place, until a manifest, the panel or playing the day sets them; the other lights and the environment dimmed to a sky light, the shadow map on, the raking light off) or off.

- `Viewer.setSunOptions({ date, time, minutes, year, month, day, latitude, longitude, north, utcOffset, followTimeline })` / `Viewer.playSunDay(playing)`
  - Change the day, the hour or the place; play the day (an hour a second).

- `Viewer.getSunPosition()` / `Viewer.getSunYear()`
  - The sun's `{ elevation, azimuth }` in degrees (azimuth from north, clockwise) and the year it is computed for.

- `Viewer.apply3IFManifestSun(location, sun)` / `Viewer.getLocationForExport()` / `Viewer.getSunForExport()` / `Viewer.disposeSunStudy()`
  - Manifest import and export; switched off when a model is unloaded.

- `solarPosition(timestamp, latitude, longitude)`, `sunriseSunset(...)`, `sunDirection(position, north)` (module exports)
  - The astronomy: the Astronomical Almanac's low-precision solar position, good to a fraction of a degree.

## `viewer/editor/weather.js`, `viewer/editor/weather-webgpu.js`

Weather (*Look > Weather*): a clear sky, fog, rain, snow or a thunderstorm around the model (`AIM3DViewer.weather`, or `?weather=<type>`). Sized from the model (`core.gridSize`); a change blends over a second or two. The sky is three's `Sky` / `SkyMesh` with clouds, its sun the sun study's or the key light's; the rain, splashes and snow are drawn wholly on the GPU from seeds, in a cube that goes with the camera (as large as the view is deep, so as dense close up as from afar) and stopped on the model's roofs by its height map seen from above; the mist is raymarched through a 3D noise over the ground and stopped by the scene's depth (a half-size depth pass with WebGL, `Viewer.renderWeatherMistDepth`; the viewport's depth with WebGPU); storms strike lightning (a bolt, a flash, thunder). The surfaces get wet and take snow where they face up (a patch of the model's materials with WebGL; built into the viewer's node materials with WebGPU, `renderer-backend.js`). The overcast scales the renderer's exposure, not the lights. The GLSL is in `weather.js`; with the WebGPU renderer the same in TSL (`weather-webgpu.js`, loaded with the renderer).

- `Viewer.setWeather(enabled)` / `Viewer.setWeatherOptions({ type, intensity, wind, windDirection, sky, surfaces, sound })`
  - On or off; any of the options (a type switches it on). `sound` plays rain, wind and thunder synthesised with WebAudio (off by default).

- `Viewer.updateWeather(delta)`
  - Every frame (`main.js` animate): the blend, the surfaces, the precipitation's uniforms, lightning, the sky, the exposure, the sound.

- `Viewer.apply3IFManifestWeather(weather)` / `Viewer.getWeatherForExport()` / `Viewer.disposeWeather()`
  - Manifest import and export; switched off when a model is unloaded.

## `viewer/editor/scene-rules.js`, `viewer/editor/scene-suggest.js`

Suggested scene (*Look > Suggested scene*): the sun, the weather, the raking light, the tone mapping and ambient occlusion picked for the model by rules, with no AI and nothing sent anywhere. The rules (`scene-rules.js`, pure, no three.js) read the facts `scene-suggest.js` gathers: the file name, the metadata shown, the manifest's describing texts (labels, summaries, metadata, annotations), the place the manifest sets, the timeline's year, the model's size in metres (`resolveModelUnit`), its kind (mesh, point cloud, Gaussian splats; IFC) and materials (textures, vertex colours, normals, unlit, triangles).

They decide first the purpose - documentation (even light, raking light for relief, no weather that would hide the geometry) or presentation (the sun of the place and time, the sky, a weather the texts name) - then the setting: outdoors, indoors or an object on its own, from keywords (English, Polish, German, matched by stem without diacritics) and the size. A year comes from the timeline, else the earliest year (1000-1989) or century ("XIV w.", "14th century", "14. Jh.") in the texts; a place from the manifest, else coordinates in the texts, else a town they name (`Viewer.lookupScenePlace`: the worker's `POST /api/geo/places`, GeoNames offline, `worker/geonames.py`; once per model, when the window opens). Splats and scans keep the lighting baked into them (no sun, no AO); a phone gets no AO and lighter weather.

Each suggestion has a confidence and its reasons; the window ticks those at least fairly sure (0.5) that change something. Nothing changes until *Apply*; *Undo* restores the sun, weather, raking light and rendering settings from before.

- `suggestScene(facts, purpose)` (`scene-rules.js`)
  - `{ purpose, autoPurpose, setting, basis, items: [{ key, value, confidence, reasons, changes, preselected }], uncertain }`; `purpose` (`"documentation"` / `"presentation"`) overrides the rules' choice. Also `findSceneKeywords`, `findSceneYear`, `findSceneCoordinates`, `sizeClass`.

- `Viewer.gatherSceneFacts()` / `Viewer.computeSceneSuggestion(purpose)`
  - The facts of the model shown; the suggestion for them (kept in `Viewer.sceneSuggestion`).

- `analyzeSceneText(text, { settings, onProgress })` (`scene-semantic.js`) / `Viewer.readSceneTextWithModel()`
  - The texts read by a sentence-embedding model in the browser (transformers.js, loaded from `viewer.sceneSuggest.semantic.library` on first use): `{ model, passages, setting, purpose, relief }` as probabilities (`scoreSemantic` of the passages against `PROTOTYPES`), kept in `Viewer.sceneSuggestion.semantic` and weighed by the rules. On a click the first time; afterwards by itself where the setting is unsure (`localStorage` `dfg3dviewer.sceneSemantic`). `Viewer.setSceneEmbedder(fn)` replaces the model (tests).

- `computeSceneShape(roots, box)` (`scene-shape.js`) / `Viewer.measureSceneShape(roots)`
  - The geometry's measures for the rules, once per model (`Viewer.sceneSuggestion.shape`): `{ up, down, sideways, groundCover, enclosure, shell, rays, triangles }`. One pass over at most 150 000 sampled triangles gives the area-weighted orientations and fills a voxel grid (48 along the longest side) with the faces' normals; 26 rays from the box's centre and from a third of its height march through it. `enclosure`: the share meeting faces turned towards them (an interior); `shell`: meeting their backs (a closed shell). The rules (`scene-rules.js`, `sceneProportions`) add them to the setting and the raking light.

- `Viewer.lookupScenePlace(facts)`
  - The place the texts name, asked of the worker once per model where none is set; the window is recomputed when it comes (`Viewer.sceneSuggestion.place`).

- `Viewer.applySceneSuggestion(keys)` / `Viewer.undoSceneSuggestion()`
  - Applies the ticked (or the given) suggestions through `setSunOptions`/`setSunStudy`, `setWeatherOptions`/`setWeather`, `setRakingLight` and `applyRenderingSettings`; puts back the scene from before.

- `Viewer.toggleSceneSuggestPanel(open)` / `Viewer.disposeSceneSuggest()`
  - The window; closed and forgotten when a model is unloaded.


## `viewer/editor/webxr.js`

VR and AR in the browser (the toolbar's headset button, shown when the browser offers one of them). VR stands the viewer on the model's ground, where the camera was, at real size (the model unit); a controller's trigger teleports to the spot on the ground it points at. AR shows the model in the room, on a table (0.6 m) or at real size, without the background and the grid. On iPhone and iPad (no WebXR) the model is exported to USDZ, in metres, for AR Quick Look.

- `Viewer.checkXRSupport()` / `Viewer.isXRAvailable()`
  - Ask the browser for `immersive-vr`, `immersive-ar` and AR Quick Look; resolves to `{ vr, ar, quickLook }`.

- `Viewer.startXR("vr" | "ar")` / `Viewer.stopXR()` / `Viewer.isXRPresenting()` / `Viewer.getXRMode()`
  - Start or end a session. The camera goes into a rig scaled to scene units per metre; the session drives the render loop, and post-processing, the comparison view and the view helper step aside. Everything is put back when it ends, or when it fails to start.

- `Viewer.getXRPlacement(mode)` / `Viewer.setXRArScale("table" | "real")`
  - Where the viewer stands: `{ position, rotationY, scale, ground }`.

- `Viewer.exportUSDZ()` / `Viewer.openQuickLook()`
  - The models as a USDZ Blob, standing on the floor; opened through a `rel="ar"` link.

- `Viewer.toggleXRPanel(open)` / `Viewer.isXRPanelOpen()`
  - The panel with the VR, AR and Quick Look buttons.


## `viewer/editor/tour.js`

Guided tour through the model's annotations, in marker order. Each step flies the camera to the annotation's saved view (`view: { position, target, fov }`, captured with the "Save current camera view" box in the annotation dialog and kept in the XML/3IF exports) or, without one, to a view along the annotated faces' normal. Settings: `viewer.tour` in `viewer-settings.json`; URL overrides `tour`, `tourAutoplay`, `tourStep`, `tourInterval`.

- `Viewer.startTour(options)` / `Viewer.stopTour()` / `Viewer.toggleTour()`
  - Open or close the tour panel. Also available as "Start guided tour" in the annotations toolbar menu.

- `Viewer.goToTourStep(index)` / `Viewer.nextTourStep()` / `Viewer.previousTourStep()`
  - Move between steps; indices wrap around. `N`/`P` (or PageDown/PageUp) on the canvas, arrows inside the panel, `Esc` closes. Clicking a marker jumps to its step.

- `Viewer.playTour()` / `Viewer.pauseTour()` / `Viewer.toggleTourPlayback()`
  - Autoplay. Dragging or zooming the model pauses it.

- `Viewer.resolveTourStepView(entry)`
  - Camera position/target/FOV used for an annotation.

- `Viewer.updateTour(time)`
  - Advances the camera flight; called from the render loop.


## `viewer/editor/face-area-selection.js`

Point clouds have no faces: in picking mode a click on a cloud (`openAnnotationDialogWithAutoPicking()` turns it on and says so) opens the annotation dialog for a **point annotation** at the picked point (`Viewer.startPointAnnotationAt(worldPoint)` in `editor/annotations.js`), stored like the point annotations of IIIF manifests: `{ targetId: "m0:root", point: [x, y, z] }` in the model root's space. Being anchored by position, they also work on streamed (Potree / 3D Tiles) clouds.

Face selection in picking mode (used to create annotations): click selects one face, Ctrl/Cmd + click adds or removes a face (Shift + click still works), Shift + drag selects every face visible inside the rectangle, Ctrl/Cmd + Shift + drag removes them. Enter opens the annotation dialog for the selection, Esc clears it.

- `Viewer.pickVisibleFacesInRect(left, top, right, bottom)`
  - Faces (`{ object, faceIndex }`) visible inside a rectangle in client pixels. Renders the rectangle into an off-screen ID buffer (mesh index, then triangle index), so occluded and back faces are skipped and section planes are respected.

- `Viewer.pickModelAt(clientX, clientY)` (`editor/picking.js`) — the model point under a page position (point clouds picked on the GPU, meshes by raycast), or `null`
- `Viewer.applyFaceSelection(hits, { subtract })` (`editor/picking.js`)
  - Adds faces to the selection, or removes them with `subtract`.

- `Viewer.refreshSelectionOverlays()` (`editor/picking.js`)
  - Draws the selection as one merged overlay per mesh; changes are batched through `scheduleSelectionOverlayRefresh()`.


## `viewer/ui/view-helper.js`

- `Viewer.initViewHelper()` / `Viewer.renderViewHelper(delta)` / `Viewer.handleViewHelperClick(event)`
  - Axes gizmo drawn in a corner of the canvas. Clicking an axis turns the camera to look along it. Hidden in presentation mode, with `hideUi`, and on canvases smaller than 320 px.


## `viewer/ui/validation-report.js` and `viewer/ui/feature-icons.js`

Is the open model ready to publish? The report (File > Validation report; in the classic toolbar the main menu) checks the manifest the viewer would export now (`build3IFManifest()`) attribute by attribute (`manifesto/manifest-inspection.js`) and, for a model a worker serves (`/files/<id>/...`), its model file (the worker's `validation.json`). One row per check - the model file, the IIIF structure, metadata and rights always, then every feature the manifest sets - each with Pass / Needs review / Fail / Not set and its issues; overall "X/Y passed". Styles: `css/validation-report.css`.

- `Viewer.toggleValidationReport()` / `Viewer.closeValidationReport()` / `Viewer.isValidationReportOpen()` / `Viewer.refreshValidationReport({ refresh })` / `Viewer.downloadValidationReport()`
  - The download is the whole report as JSON (rows, the model's `validation.json`, the manifest inspection).
- `buildValidationReport(manifest, modelReport)` -> `{ rows, passed, total, status, inspection, modelReport }`
- `fetchModelValidation(modelUrl)` / `modelValidationUrl(modelUrl)`
  - `GET /api/model/validation/<id>` for a worker model, null otherwise; cached per session.
- `featureIconsCaption(inspection, modelValidation)` / `statusIconPart(icon, label, status, count)` / `modelCheckPart(validation)` / `featureIconSvg(icon)`
  - The icons of the model lists: what a manifest contains (example manifests list) and the model file check (worker models list), coloured by status.

## `viewer/ui/menu-toolbar.js`

The toolbar as menus with names (Look, Analysis, Measure, Story, Model, File, Device, Settings) instead of one row of icons: the same tool buttons `editor-toolbar.js` builds, with their submenus and state, sorted into the menus; submenus open in place. The default; `?ui=classic` or `viewer.ui: "classic"` keeps the classic toolbar. The sun and the raking light (out of Lights), the comparison, the tour, the photos and the annotation and IIIF import/export (out of Annotate) are tools of their own here. The transform modes (orbit, move, rotate, scale), the camera reset and full screen stay at hand outside the menus, and so do AR (the app's, else the browser's WebXR) and the app's motion look - on a phone set off on the right, AR as an accent pill; the projection is under Look, and Settings holds the language and theme of the classic main menu (its cog is not shown). Styles: `css/menu-toolbar.css`.

- `isMenuToolbarEnabled(viewer)` / `buildMenuToolbar(viewer, toolbar, host, buttons)`
  - The layout follows the viewer's size (`data-mode` on the toolbar): `desktop` (a bar in the bottom left corner, a menu opening as a panel above its name), `bar` (narrower than 700 px: five tabs along the bottom, the rest under More, a menu as a sheet) and `rail` (a touch screen on its side, up to 520 px high: the tabs down the left edge, a panel beside them). Between layouts the tabs move to their new places and turn a quarter, the way `screen.orientation` says the phone turned (not with reduced motion).

- `Viewer.openToolbarMenu(id)`
  - Opens a menu (`look`, `analysis`, ..., `more`), or closes it with `null`. Escape, a tap outside and, on a phone, a tool panel opening close it too. `Viewer.isToolbarMenuOpen()`: whether one is open (`ui/back-navigation.js`).

- `updateMenuToolbarLabels(viewer)` / `updateMenuToolbarState(viewer)`
  - Called from `updateEditorToolbarLabels()` and `updateEditorToolbarState()`: the menus' names, and the comparison button (shown where `Viewer.canCompare()`).


## `viewer/editor/context-menu.js`

The actions for the point under the pointer: a right click that did not move (a right-drag still pans), a press and hold of one finger or pen (500 ms, not while drawing a point cloud profile), or the ContextMenu key / Shift+F10 (the centre of the canvas, the first item focused). On an IFC element it picks it first, as a tap does (highlight and properties). A quick tap of two fingers together is a step back (`Viewer.goBack()`). Styles: `css/context-menu.css`.

- `Viewer.openContextMenu(clientX, clientY, { focus })` / `Viewer.closeContextMenu()` / `Viewer.isContextMenuOpen()`
  - Items in groups, where they apply. Measuring: Finish measurement, Remove last point (`undoMeasurementPoint()`), Discard measurement, Stop measuring - a phone's Enter and Backspace. Picking faces: Annotate selected faces (n), Clear selection, Stop selecting faces. Otherwise the IFC element (its name as the title): Ask about this element (`askAboutIfcSelection()`, with a lock where the plan lacks it), Select all of this type and Show only this element (no AI: `showIfcSelectionMatches(kind)`), Hide element, Copy GlobalId; Show hidden elements (n), Show all elements; the point: Zoom to this point, Measure from here, Annotate here (`startPointAnnotationAt`), Cut horizontally here (`cutHorizontallyAt`, the part above cut away), Copy coordinates; the view: Remove sections, Reset view. Measure, annotate and cut only where the toolbar offers the tool. A press outside, the wheel, a resize or a step back close it.

- `Viewer.consumeContextMenuPointer(event)`
  - True for the release of the press and hold that opened the menu, and for the fingers of a gesture of two or more (pinch, two-finger tap): `onPointerUp` does not take them as taps.

- `Viewer.showIfcSelectionMatches("sameType" | "isolate")` (`viewer/ai/ifc-query.js`)
  - The elements with the picked element's IFC type object (else its class) highlighted, or the element alone shown, with the IFC question tool's view (`resetIfcQueryView()`, a step back undoes it). Returns the number of elements.

- `Viewer.askAboutIfcSelection()` (`viewer/ai/ifc-query.js`)
  - Opens the IFC question window about the picked element: it is shown above the examples (removable with ×), the examples become questions about it, and its fields, storey and property values go to the worker as `selection`.

## `viewer/ui/back-navigation.js`

Back: one step out of what is open, the last layer first - the context menu, a toolbar menu, the annotation, materials and shading dialogs, a panel window, the IFC question window, elements highlighted or isolated, the IFC properties, the metadata window, the tour, the last point of a measurement being drawn, the selected faces. Taken by Escape, the mouse's back button, a two-finger tap and the back gesture.

- `Viewer.goBack()` / `Viewer.canGoBack()`
  - `goBack()` closes the topmost open layer; false when nothing was open. Escape takes it when no other handler used the key (`preventDefault`) and not in a field with text; so does the mouse's back button over the viewer (the browser's own back only when nothing was open).

- History (a touch screen or the app, not in an iframe): while something is open the page has one history entry of its own (`history.state.explora4dBack`), so the back gesture or Android's back button closes one layer instead of leaving the page; the entry goes again when everything is closed by its own buttons.

## Compressed glTF and progressive loading (`viewer/loaders.js`)

GLB/glTF models are decoded with Draco (`assets/draco/`), Meshopt and KTX2/Basis (`assets/basis/`, one shared transcoder).

When `<model>.preview.glb` exists next to the model (HEAD probe; `viewer.progressive.enabled`, URL `preview=0|<url>`), the preview goes through the normal load (`afterLoad`: settings, camera, metadata), then the full model is fetched in the background and `swapInFullModel()` replaces the preview root in place: same root transform, materials setup, section outline, animations, hierarchy and statistics (`refreshModelHierarchyAndStats()` in `metadata.js`), annotation markers. The camera does not move. Annotations cannot be created while the preview is on screen (`Viewer.isPreviewModelActive()`), because they store face indices of the full model. `window.viewer.fullModelLoaded` turns true once the full model is in place.


## `viewer/up-axis.js` and `viewer/editor/up-axis.js`

Models whose up is not three.js' +Y: Z-up exports (CAD, scans, photogrammetry) and models upside down. `upAxis` names the axis of the file that points up (`Y+` default, `Y-`, `Z+`, `Z-`, `X+`, `X-`; `normalizeUpAxis()` also reads `z`, `-z`, `z-up`).

- `applyUpAxis(root, upAxis)` turns that axis to +Y without touching the root's own transform, so it composes with what `afterLoad` resets and what metadata, config, manifests and the editor set: a group root gets an inner pivot (`userData.isUpAxisPivot`) holding its children; a mesh or point root (STL, PLY, XYZ, ...) has its geometry turned. Repeated calls replace the fix; tiled models are skipped (oriented by `tiles.js`). `getUpAxis(root)` reads it back (`userData.appliedUpAxis`).
- Applied at the start of `setupObject()` (`viewer-utils.js`), before the metadata/config transform and the grid placement. Sources, first wins: URL `?upAxis=`, the model's `_viewer.json` (`upAxis`, saved with the rotation), its `objectsConfig.models` entry (`upAxis`; for an AIM3D manifest, `AIM3DViewer.modelTransform.upAxis` of the first model).
- `swapInFullModel()` gives the full model the preview's fix; annotation target paths (`editor/picking.js`) skip the pivot, so they do not change with the up axis.
- Editor: *Up axis* in the toolbar's transform group (*Model* menu) — `Viewer.setUpAxis(axis)` turns the model, puts it back on the grid and refreshes the section outline, clipping, face picking and annotation markers; `Viewer.getModelUpAxis()`. Exported to and imported from `AIM3DViewer.modelTransform.upAxis`.

## `viewer/tiles.js`

Streamed level-of-detail models through [3d-tiles-renderer](https://github.com/NASA-AMMOS/3DTilesRendererJS): 3D Tiles (`tileset.json`) and Potree 2 (`metadata.json`), detected by file name or `?format=3dtiles|potree`.

- `loadTiledModel({ url, format, configureGLTFLoader, onModel })`
  - Creates the `TilesRenderer` with the viewer's glTF decoders (Draco, Meshopt, KTX2), `ReorientationPlugin` (georeferenced tilesets moved to the origin; local ones turned from Z-up to Y-up), `PotreePlugin` or `PointCloudEffectsPlugin` (Eye-Dome Lighting, point shape). Resolves with the tiles group once the first tiles are in; `loaders.js` then runs the normal `afterLoad` on it.
  - Adds an invisible `Object3D` carrying a box geometry of the whole tileset, so centring, camera framing and dimensions use the full extent rather than the coarse root tiles.
- `updateTiles()` — called from the render loop; `disposeTiles()` — on model reset.
- Orientation: `isGeocentric()` decides between 3d-tiles-renderer's `ReorientationPlugin` (Earth-centred tilesets, laid flat at their place on the globe) and `orientLocalTileset()` (Z up turned to Y up, centred). The plugin alone took any centre farther than half the Earth's radius for ECEF, which tilted scans in UTM / Gauss-Krüger coordinates; now the centre must also be more than 10 km off the equatorial plane (`viewer.tiles.georeferenced` overrides).
- Potree: `decodePotreeClassification(loader)` adds the `classification` attribute PotreeLoader does not decode; `getPotreeAttributes()` — the cloud's attributes with their min/max from `metadata.json` (the point cloud panel offers intensity / classification colours by them); `getTiledModelBox()` — the whole tileset's world box (height colours).
- Annotations are not offered for tiled models (their meshes change with the level of detail); measurements work on the tiles currently loaded.


## `viewer/pointcloud-las.js`

Direct LAS/LAZ loading (drag and drop, `?model=scan.laz`), without server conversion. Loaded on demand by `loaders.js`, so loaders.gl and laz-perf (WebAssembly embedded, nothing fetched from a CDN) only download with the first such file. The file is downloaded and decoded in a Web Worker (`pointcloud-las-worker.js`) and arrives in batches of 100 000 points, so the page stays responsive and the cloud fills in while it loads.

- `loadLasPointCloud(url, { name, onProgress, compressed })`
  - Resolves once the first batch is in with `{ object, done }`: `object` is the model root (a `Group` holding the `Points`), `done` resolves with the cloud's info when all points are in. `loaders.js` runs `afterLoad` on the first batch and sets up the point cloud panel and the stats on `done`; `window.viewer.fullModelLoaded` stays `false` (and `core.progressiveLoad` holds `{ pointCloud }`) until then.
  - The buffers are allocated for the whole (thinned) cloud from the LAS header and filled batch by batch (`addUpdateRange`, draw range); the bounds come from the header (rounded like the Float32 positions), so camera framing and grid placement are right from the first batch. A file with fewer points than its header announces gets buffers of its real size at the end.
  - Positions are re-centred in double precision before converting to Float32, so UTM / national-grid coordinates keep millimetre precision. The original centre is kept in `points.userData.pointCloud.originOffset`.
  - Thins to `viewer.pointCloud.maxPoints` (every n-th point) using the point count from the LAS header (toast `pointCloudThinned`).
  - Colours: RGB when present, else intensity, else a height ramp, decided by the first batch. Z-up is turned to Y-up; points are drawn at a fixed screen size.
  - `points.userData.pointCloud`: `{ totalPoints, loadedPoints, skip, colorMode, originOffset, loading, decoder }` - `loading` is `true` until all points are in (the point cloud panel waits for it), `decoder` is `"worker"` or `"main-thread"`.
  - Where a module worker cannot start (no module workers, the bundle served from another origin), the same decoder runs on the main thread. Removing the model from the scene while it loads stops the worker.

## `viewer/pointcloud-material.js`

Display of directly loaded point clouds (LAS, LAZ, XYZ, PCD), used by the point cloud panel. The cloud's `PointsMaterial` is replaced by 3d-tiles-renderer's `PointCloudMaterial` (the material streamed clouds get from `PointCloudEffectsPlugin`, imported through the package's `./src/*` export - not public API, check it on package updates), so both kinds draw alike.

- `preparePointCloudMaterial(points)` — swaps the material once (keeps vertex colours, opacity, clipping planes) and injects the colour modes into its vertex shader; attaches the Eye-Dome Lighting pre-pass.
- `setPointColorMode(points, mode)` — `rgb`, `intensity`, `height` (world Y) or `classification` (ASPRS colours, `CLASSIFICATION_COLORS`): a uniform (`uColorMode`) and the range uniforms; the buffers are never rewritten.
- `setPointSize(points, { sizeMode, scale, pixels })` — `adaptive`: `material.size` in world units = spacing × 1.4 × scale, at least 1 px; `fixed`: `pixels × scale` px.
- `estimatePointSpacing(geometry)` — average neighbour distance, assuming the points sample surfaces: the occupied cells of a 64-step grid over the cloud (from at most 300 000 sampled points) give the surface area, shared out among the points. Cached in `points.userData.pointSpacing`.
- `addColorModes(material, colorUniforms)` / `createColorUniforms()` — the same colour modes on another `PointCloudMaterial`: the point cloud panel adds them to every tile of a streamed cloud, all sharing one set of uniforms, so a mode switch is a single uniform change.
- `setPointEdl(points, strength)` — Eye-Dome Lighting: in the cloud's `onBeforeRender` it is drawn into a float log-depth target with a separate material (three would otherwise keep the uniforms of the material it drew last), then the main material shades each point by its neighbours' depth. Skipped while `0`, in WebXR and outside WebGL.

## `viewer/pointcloud-las-decode.js`

The LAS/LAZ decoder shared by the worker and the main-thread fallback (no three.js, no DOM). Emits `progress`, `header`, `batch` (Float32 positions relative to the cloud's centre, Uint8 RGB, Uint16 intensity, Uint8 classification - transferred, not copied) and `done` messages.

- `decodeLasUrl(url, { maxPoints, compressed, emit })` — downloads with `fetch`. Uncompressed LAS is decoded record by record while it downloads, without keeping the file in memory (so a multi-GB scan only costs the memory of the points kept), for all point formats 0-10 (LAS 1.0-1.4); the download stops once the header's point count is reached. LAZ is downloaded in full and decompressed in batches by laz-perf (point formats 0-3). `compressed: null` tells LAS from LAZ by the header (blob: URLs have no file name).
- `decodeBuffer(buffer, { maxPoints, emit })` — the same for a file already in memory.
- `readLasHeader(buffer)` — version, point format and record length, point count (1.4 64-bit count included), scale, offset, bounds (`null` when the header has none); `readLasPointCount(buffer)`.

## `viewer/pointcloud-las-worker.js`

The Web Worker entry: posts `ready` once loaded (a worker that fails before that falls back to the main thread), then runs `decodeLasUrl` for the request it is sent. Started as `new Worker(new URL("./pointcloud-las-worker.js", import.meta.url), { type: "module" })`, which Parcel bundles by itself and the `moduleWorkers()` plugin in `rollup.config.js` emits as a chunk of its own.


## `viewer/splats.js`

Gaussian splats (3D Gaussian Splatting captures: `.spz`, `.splat`, `.ksplat`, `.sog`, `.rad`, and a `.ply` whose vertices are Gaussians), drawn with [Spark](https://sparkjs.dev) together with the meshes of the scene, in VR and AR too. Loaded on demand by `loaders.js`, so Spark (WebAssembly and workers embedded) only downloads with the first splat file. Example: `examples/tempietto/Tempietto.splat` (built by `scripts/build-tempietto-examples.mjs`).

- `buildSplatModel(buffer, { fileName, name, upright })`
  - A group holding the `SplatMesh`, turned upright (captures are stored Y down). The mesh gets a geometry with the corners of its bounds, so framing, the grid and measurements see it; `userData.gaussianSplats` holds `{ count, format }`.
  - From 300 000 splats on, Spark builds a level-of-detail tree while loading and draws a budget of splats per frame; a `.rad` (Spark's format, written by its `build-lod` - the worker makes one of every uploaded capture) brings the tree ready-made, and its bounds and count are those of the tree, merged inner splats included.
  - Adds Spark's renderer (`core.sparkRenderer`, `spark-renderer` in the scene) once; `resetLoadedModelState()` removes it.
- `buildPagedSplatModel(url, { fileName, name, upright })`
  - A `.rad` on a server, paged: Spark reads its header by an HTTP range request and then fetches the tree in chunks of 64K splats, the coarse root first and finer chunks where the camera looks, so the capture shows after a few hundred kB and sharpens while it is viewed; only what is seen takes GPU memory. The bounds come from the root chunk, the count from the header (`userData.gaussianSplats.paged` is `true`). Resolves to `null` when the server answers the probe range with the whole file (`200`); `loaders.js` then loads it with `buildSplatModel()`, as it does a `.rad` opened from a File. Example: `examples/tempietto/Tempietto-lod.rad` (`Tempietto.splat` through `build-lod --rad`).
- `isSplatPly(buffer)` (in `loaders.js`) — tells a PLY of Gaussians (`f_dc_0`, `scale_0`, `rot_0`, or a compressed `packed_position`) from a mesh or point PLY.


## `viewer/renderer-backend.js` and `viewer/rendering-webgpu.js`

The renderer, chosen once when the viewer starts: three's WebGLRenderer (default) or, with `viewer.renderer` / `?renderer=` set to `webgpu` or `auto`, its WebGPURenderer - only where `navigator.gpu` exists and the model is not a point cloud or splat scene (`modelNeedsWebGL()`: WebGPU has no point size, Spark needs WebGL). `core.rendererBackend` is `"webgl"` or `"webgpu"`; `core.rendererDevice` says what the WebGPU renderer runs on (`"webgl2"` with `&webgpuBackend=webgl2`, for tests).

With WebGPU:
- the loaders' materials are converted to node materials by three; the dimmed direct specular light that `setupSingleMaterial()` patches into the WebGL shaders comes from a lighting model registered for MeshStandard/MeshPhysical materials;
- `applyWebGPURendering()` builds a TSL `RenderPipeline` for post-processing and ambient occlusion (GTAONode on a normal/depth pre-pass, applied to the indirect light); SMAA and FXAA use multisampling;
- section planes clip through clipping groups (the model roots and the section fill get ClippingGroup's flags, `updateActiveClippingPlanes()`);
- `captureWebGPUFrame()` reads the view back from a render target - thumbnails and `window.viewer.captureFrame()` use it - and `createFaceIdMaterial()` draws the ID buffer of the area selection, read back asynchronously (`pickVisibleFacesInRect()` then returns a promise);
- left out, with a message: the custom GLSL scan view, the tone mapping previews, WebXR (AR Quick Look stays, `editor/webxr.js`), and opening point clouds or splats (they need the viewer opened with WebGL).

Closed lines are `Line`s back to their first point: the WebGPU renderer draws no `LineLoop`.


## `viewer/editor/point-cloud-panel.js`

Point cloud panel, shown in the side stack when the model is a point cloud (hidden in presentation mode and with `hideUi`).

- `Viewer.setupPointCloudControls(root)` — called after a model is added (and after a progressive swap, and once a LAS/LAZ cloud has all its points); builds the panel when `root` contains `THREE.Points` or is a streamed cloud.
- Direct clouds (LAS/LAZ/XYZ/PCD): `setPointCloudSize(factor)` (×0.25-×4), `setPointCloudSizeMode('adaptive'|'fixed')`, `setPointCloudShape('square'|'round'|'sphere')`, `setPointCloudEdl(0..1)`, `setPointCloudColorMode('rgb'|'intensity'|'height'|'classification')` — all shader uniforms of `pointcloud-material.js`, one set per `THREE.Points`.
- Streamed clouds (3D Tiles, Potree): size (material size, Potree `pointScale`, minimum pixel size), shape, `setPointCloudEdl(0..1)`, colour `rgb`, `intensity` / `classification` (Potree clouds that carry them), `height` or `tile` (level-of-detail colours; 3D Tiles tiles get their tree depth as the id) — one set of colour/filter uniforms shared by all tiles (`state.colorUniforms`). `applyPointCloudSettingsToTile(scene)` applies the settings (and GPU picking) to tiles loaded now and later.

## `viewer/editor/point-cloud-tools.js`

Point cloud tools in the panel, working through the cloud's shader uniforms (`Viewer.getPointCloudUniformSets()`), so the view, the Eye-Dome Lighting pre-pass and GPU picking all see the same points.

- Classes: a check box per class present (`state.classes`: id -> count for a direct cloud, counted from the `classification` attribute; for a streamed cloud collected as tiles load, `notePointClassesOfTile(scene)`), with the ASPRS name and colour. `setPointCloudClassVisible(classId, visible)` — `uClassHiddenMask` bits 0-31 (`uOtherClassVisible` for 32-255); hidden points are moved out of the clip volume in the vertex shader. Shown when there are at least two classes.
- Profile (cross-section): `startPointCloudProfile()` — the next two clicks on the cloud (`picking.js` -> `addPointCloudProfilePoint`) are the ends of a line; `setPointCloudProfile(a, b, { width, view })` — only a vertical slab along the line stays (`uProfilePlane`, `uProfileHalfWidth`, `uProfileAxis`, `uProfileRange`), the line is drawn on the cloud, and `viewPointCloudProfile()` turns to an orthographic view square to the slab, fitting the line's length and the cloud's height. `setPointCloudProfileWidth(width)` (panel: log scale from 1/2000 to 1/5 of the cloud's diagonal; default 4 point spacings, at least 0.4 % of the diagonal); `clearPointCloudProfile()` removes it and goes back to the perspective view if that was on before. Measurements on the slab use the same GPU picking.

## `viewer/pointcloud-picking.js`

GPU picking of point clouds: the point under the cursor, exactly as drawn. Used by `editor/picking.js` (`getPrimaryModelIntersection`: ruler, annotations, double-tap focus, profile clicks) whenever a point cloud is loaded.

- `pickPointCloud({ renderer, camera, roots, ndc })` — draws the clouds once more into a float target (`RGBA32F`, the drawing buffer's size), scissored to a square of ±6 CSS px around the cursor, every point writing its object id and its index (`gl_VertexID`) instead of its colour (`PICKING_PASS` in `pointcloud-material.js`); reads those pixels and returns the point nearest the cursor as a Raycaster-like hit `{ point, object, index, distance, isPointCloudHit }`, `null` over empty space, `undefined` without float render targets (then the raycast picks points as before). Point size and shape, hidden classes, the profile slab and clipping planes all count. Clouds take part once their material has the colour modes.
- `setPointRaycastSkipped(points)` / `withoutPointRaycast(callback)` — the CPU raycast leaves such clouds out while meshes are raycast next to them; the nearer of the two hits wins. The raycast tests every point against a distance in world units (`Raycaster.params.Points.threshold`, 1 by default) - on a 100 000-point scan it returned a point 1.8 m from the one under the cursor.
